# Agents: tools are a contract

In your existing repository, inspect the agent definitions you already use and the CLI `/agent` list. Verify tool names, selection and effective instructions before asking for path/line evidence and a test proposal; collisions between `.github`, `.claude` and personal sources have differing descriptions in current docs. The optional [focused investigator](../../examples/agents/focused-investigator.agent.md), [repository reviewer](../../examples/agents/repository-reviewer.agent.md) and [no inheritance](../../examples/agents/no-inheritance.agent.md) show exactly **Copilot CLI tool names** `view`, `grep`, `glob`: a read-oriented selection without CLI `bash`, `edit` or `create`. They need not be installed for your project. These names are not a universal schema for other Copilot hosts/editors; source review and local frontmatter validation do **not** prove a runtime OS read-only boundary. [source:cli-reference]

Separate built-in roles from custom agent definitions; `/rubber-duck` is available in installed help, but don't assume a six-way automatic selector. If the integrator needs changes, have it own edits and acceptance checks after investigations. A custom subagent normally excludes repository custom instructions unless `include-custom-instructions: true`; main-agent selection has different semantics.
