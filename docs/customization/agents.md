# Agents: tools are a contract

Review [focused investigator](../../examples/agents/focused-investigator.agent.md), [repository reviewer](../../examples/agents/repository-reviewer.agent.md) and [no inheritance](../../examples/agents/no-inheritance.agent.md). All specify exactly **Copilot CLI tool names** `view`, `grep`, `glob`: a read-oriented selection without the CLI `bash`, `edit` or `create` tools. These names are not a universal schema for other Copilot hosts/editors; source review and local frontmatter validation do **not** prove a runtime OS read-only boundary. Ask for path/line evidence and test proposal. To adapt one for your project, inspect CLI discovery locations and `/agent` list; collisions between `.github`, `.claude` and personal sources have differing descriptions in current docs. Verify selection and effective instructions in-session before using it. [source:cli-reference]

Separate built-in roles from custom agent definitions; `/rubber-duck` is available in installed help, but don't assume a six-way automatic selector. If the integrator needs changes, have it own edits and acceptance checks after investigations. A custom subagent normally excludes repository custom instructions unless `include-custom-instructions: true`; main-agent selection has different semantics.
