# Instructions: attach only what is needed

Start with root `CLAUDE.md`, don't rename it on day one. Copilot recognizes it along with `.claude/CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.github/copilot-instructions.md`, path-scoped `.github/instructions/*.instructions.md`, and (v1.0.89) `.claude/rules`. Adding another root policy risks contradictions. Repository-relative `@` imports are allowed within repository/custom boundaries but not absolute or `~` imports; `GEMINI.md` and `*.instructions.md` do not expand those imports. Inspect `/instructions` and `/env` after restart/resume for actual attachment. [source:instructions-reference] [claim:rules-added]

**Try it:** start [first 15 minutes](../start/first-15-minutes.md) with `--with-config`, inspect the copied `CLAUDE.md` and `guidance/shared.md`, then check `/instructions` in the lab session. The copy retains the import rather than generating a replacement policy. In your real repository, keep *its own* `CLAUDE.md`: compare attachment on a file inside and outside a nested rule's scope before adding another policy. The [coexistence example](../../examples/coexistence/CLAUDE.md) demonstrates a matching `packages/catalog` path; static formatting alone cannot establish runtime priority. Agents acting as subagents default to not including repository instructions; set `include-custom-instructions: true` only when needed and verify attachment.
