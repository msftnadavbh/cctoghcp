# Instructions: attach only what is needed

Start with root `CLAUDE.md`, don't rename it on day one. Copilot recognizes it along with `.claude/CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.github/copilot-instructions.md`, path-scoped `.github/instructions/*.instructions.md`, and `.claude/rules` in supported versions. Adding another root policy risks contradictions. Repository-relative `@` imports are allowed within repository/custom boundaries but not absolute or `~` imports; `GEMINI.md` and `*.instructions.md` do not expand those imports. Inspect `/instructions` and `/env` after restart/resume for actual attachment.

**In your checkout:** read its `CLAUDE.md` and imports first. Start Copilot there, inspect `/instructions` and compare attachment on a file inside and outside a nested rule's scope before adding another policy. The [coexistence example](../../examples/coexistence/CLAUDE.md) is optional practice; static formatting alone cannot establish runtime priority. Agents acting as subagents default to not including repository instructions; set `include-custom-instructions: true` only when needed and verify attachment. [Compatibility](../migration/compatibility.md).

For [token economy](../workflows/token-economy.md), keep **durable** repository conventions, the actual approved checks and recurring pitfalls in the existing `CLAUDE.md`; keep cross-project preferences in their proper personal scope. **Before:** a giant root file mixes all release/debug procedures and an architecture manual with everyday rules. **Better:** retain canonical essentials in `CLAUDE.md`, place genuinely file-scoped guidance in scoped rules, reuse `.claude/skills` for occasional workflows, and reference architecture docs when the subsystem task calls for them. Keep essential rules even when they make the file longer; these examples do not require new files.

For example, a literal `@docs/large-architecture.md` inside a supported instruction file **eagerly reads** that document (and supported nested imports); the ordinary sentence “Consult `docs/large-architecture.md` when working on that subsystem” lets the agent read it as needed. Copilot combines applicable instructions and removes some *identical* user/repository/agent copies; do not assume double token cost for exact duplicates, or deduplication for near-duplicates and conflicting paraphrases. There is no general precedence order. A `.claude/skills` description supplies discovery metadata; its `SKILL.md` instructions load when invoked, and referenced supporting resources remain available for that task. Verify invocation rather than assuming discovery means use. Inspect `/instructions` after changing files and restarting/resuming; it shows attachment, not effective priority. See [skill loading](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills) and [Claude skills](https://code.claude.com/docs/en/skills).
