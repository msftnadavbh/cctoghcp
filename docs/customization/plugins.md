# Plugins: package first, activation later

You don't need a plugin to use the `.claude/skills` already copied into the [practice lab](../start/first-15-minutes.md); check `/skills` first. If you later package the three book skills, review [plugin.json](../../examples/plugin/plugin.json) and run the offline packager from the book root to an **unused path outside the book**: PowerShell `python -B -m scripts.package_plugin (Join-Path $HOME 'copilot-skills.zip')` or zsh `python3 -B -m scripts.package_plugin "$HOME/copilot-skills.zip"`. This creates an archive with the manifest and skill files; it does **not** install or activate anything. Do not overwrite an existing archive. Packaging does not install the plugin; review its contents and your CLI's install options separately.

Before installation compare your `copilot plugin install --help` with the [plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference) and inspect the unpacked archive. `update NAME` can fetch new code; it is not a cleanup step. [Installation troubleshooting](../reference/known-discrepancies.md).
