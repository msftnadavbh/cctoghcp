# Skills: one canonical text, multiple packages

Project discovery can include `.github/skills`, `.claude/skills` and `.agents/skills`; personal locations differ. `.claude/commands/*.md` can be an alternate skill source but command invocation is not identical to every Claude command. In [your existing checkout](../start/use-copilot-in-your-repository.md), keep the skills you already use. Inspect `/skills`, then explicitly request a relevant skill **if it appears**; check its answer cites your actual project rather than assuming discovery implies use. Do not create a duplicate skill to migrate the same instructions. [source:plugin-reference]

A good skill says when to use it, bounded input/output and failure stop; avoid duplicating entire company policies inside every skill. [Commands and other artifacts](../migration/compatibility.md) may need separate review. The [plugin guide](plugins.md) covers optional packaging separately; packaging does not activate a skill. [Curated examples](../reference/curated-resources.md) are for adaptation, not copied authority.
