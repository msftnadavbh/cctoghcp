# Skills: one canonical text, multiple packages

Project discovery can include `.github/skills`, `.claude/skills` and `.agents/skills`; personal locations differ. `.claude/commands/*.md` can be an alternate skill source but command invocation is not identical to every Claude command. The [first lesson](../start/first-15-minutes.md) copies three existing [.claude/skills](../../.claude/skills) when you use `--with-config`. In [first hour](../start/first-hour.md), inspect `/skills`, then ask Copilot to use `reproduction-brief` **if it appears**; check that its brief cites the current lab rather than assuming discovery implies use. Do not create a duplicate skill to migrate the same instructions. [source:plugin-reference]

A good skill says when to use it, bounded input/output and failure stop; avoid duplicating entire company policies inside every skill. The [plugin guide](plugins.md) covers optional packaging separately; packaging does not activate a skill. [Curated examples](../reference/curated-resources.md) are for adaptation, not copied authority.
