# Skills: one canonical text, multiple packages

Project discovery can include `.github/skills`, `.claude/skills` and `.agents/skills`; personal locations differ. `.claude/commands/*.md` can be an alternate skill source but command invocation is not identical to every Claude command. In this repo canonical instructions live only in [.claude/skills](../../.claude/skills); the first-15-minute optional `scripts.lab setup --with-config` copies **only those three** into the private lab (bare copies have none), so inspect `/skills` before claiming discovery. Separately, `python3 -B -m scripts.package_plugin /tmp/checkpoint-skills.zip` creates an exclusive-new deterministic package with copied skill files, without installing it. Choose a new path; inspect ZIP manifest and source before later activation. [source:plugin-reference]

A good skill says when to use it, bounded input/output and failure stop; avoid duplicating entire company policies inside every skill. `python3 -B -m scripts.validate --static-only` checks skill frontmatter and packaged content, not model discovery. [Curated external examples](../reference/curated-resources.md) are for adaptation, not copied authority.
