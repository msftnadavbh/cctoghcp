# Autopilot: agree on an end condition first

Autopilot continues a task; it does not itself grant permissions or define which edits, checks or publication you approved. It can execute checks its granted tools permit. In [your existing repository](../start/use-copilot-in-your-repository.md), use it when you can name the approved behavior, editable paths, regression case, project's real check and a clear stopping point. For small changes, manual turns may be simpler.

1. Review `/env`, `/permissions` and `/tasks`. Use `/plan` when uncertainty warrants it and verify acceptance cases against actual source. Offer only the tools needed for the stage. With limited permissions, Autopilot denies tool requests that still require approval; use manual turns for per-write approval, or continue only within previously reviewed grants. See [permissions](permissions.md), rather than broadening grants to make continuation work.
2. If continuation helps and the agreed edits are already permitted, toggle `/autopilot` and request: “Implement [approved behavior] in [agreed paths]. Cover [regression case] while preserving [public interface]. No unrelated cleanup, shell, network, commit or publication. Finish by listing changed files for my review and the real project check for me to run, marked pending. Stop on ambiguous behavior, access or scope surprises, or repeated attempts without new evidence; report the blocker.” Replace all placeholders with reviewed project facts before sending. For the beginner workflow with manual write approvals, use the same mission in manual turns.
3. Inspect `/diff`, `/tasks` and `/usage`. Exit, review all changed and new files, then run the **project's** checks yourself. Report observed exits, not Autopilot's completion message. An unexpected change or failing check returns to diagnosis, never a broader grant.

If running the check *inside* the mission has already been approved, instead request: “Implement [approved behavior] in [agreed paths], including [regression case], preserving [public interface]. Use only [the project's actual approved validation command] under the reviewed permissions. Finish when behavior and check pass; report changed files, actual result and any blocker. No unrelated cleanup, commit or publication. Stop if required access is unavailable, scope is insufficient or repeated attempts produce no new evidence.” This alternative does not authorize a new command or widen permissions. Prompt stop conditions guide collaboration; they are not runtime-enforced retry limits.

`/settings stayInAutopilot false` changes whether the mode remains on after a task; check the effective setting and mode again on resume. Set an explicit `--max-autopilot-continues 3` (or another reviewed count) at launch: this limits **continuation messages**, not model calls, credits, time, child processes or tools. The [public-preview limit](../reference/known-discrepancies.md) `/limits set max-ai-credits 30` is soft; an in-progress response may finish over it, and official pages disagree on whether it resets per response or lasts the interactive session. Inspect `/usage`. Esc twice interrupts work, not edits or external effects. [Token economy](token-economy.md) discusses repeated work; [permissions](permissions.md) and [sessions](sessions-and-context.md) cover the other controls. Headless use is an [optional advanced integration](headless-and-ci.md).
