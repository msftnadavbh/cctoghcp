# Autopilot: objective, permission, budget, observation

Autopilot is a **continuation policy**, not an operating-system sandbox, Git publisher, or substitute for review. Planning, autonomy, tool approval and parallelism are four separate axes. Installed 1.0.89 help offers `/autopilot`, `--autopilot`, `--max-autopilot-continues` (default five) and `--no-ask-user`. Configuration help reports `stayInAutopilot` default `true` after a task completes; in a separately approved interactive session `/settings stayInAutopilot false` changes that preference. Check the actual mode at the start of **every** resumed task; don't assume completing an objective resets it. [source:cli-reference]

## One reviewed interactive cycle

Work on the repaired private copy from [first hour](../start/first-hour.md). First run the external `in-stock` oracle from the trusted root and record its initial expected failure; **do not** invite the agent to execute edited code before human code review. Start `copilot -C '/tmp/my catalog lab' --no-auto-update --no-remote-export --disable-builtin-mcps --disallow-temp-dir --available-tools=view,grep,glob,edit,create` only after reviewing CLI config, auth and the selected workspace. Check `/env`, `/permissions`, `/context`, `/limits`. This visible tool set excludes shell; temp-dir flag removes an automatic grant, **not** the reviewed cwd under `/tmp`. Tool approval and path permissions still need separate scrutiny; runtime handling here was not tested. Plan with `/plan`, inspect `plan.md` (Ctrl+Y where supported), and have the human accept the twelve-field [contract](planning.md).

Then toggle `/autopilot` and give an *observable*, bounded objective:

> Implement approved optional `in_stock=None|bool` in `src/catalog.py` and focused `tests/test_catalog.py`. First filter products, then paginate; preserve totals, unfiltered output and the earlier validation repair; CLI `--in-stock` accepts only true/false. Change no other file, do not run shell/network or publish. Finish after presenting a complete diff and named tests for **human** execution; stop if a permission, unexpected path or ambiguous input blocks progress.

Approve only tool/path requests you actually reviewed. A `write(src/catalog.py)` *relative* pattern can match trailing components elsewhere; the interactive manual-approval route is preferable to a claim that the flag locks down the filesystem. Expect a reviewable diff and tests **proposed**, not silently executed by a hook. If it requests an unapproved tool, stop, inspect the request and revise plan; never reflexively enable `--allow-all-tools`. After completion: `/diff`, `/tasks`, `/usage`, `/exit`, inspect files from trusted terminal; then run the external `validation` and `in-stock` oracles with `python3 -I -B` **only after** reviewing executable changes. An unexpected denied action is a successful boundary observation; whether the CLI consistently enforces this candidate has **not** been authenticated-runtime tested here. [claim:selective-tools]

## Headless is a separate, unverified integration

`copilot -C '/tmp/my catalog lab' --autopilot --max-autopilot-continues 3 --no-ask-user -p 'Inspect the reviewed catalog copy; report only, no edits or shell' --available-tools=view,grep,glob --allow-tool=read --no-remote-export --disable-builtin-mcps --no-auto-update --disallow-temp-dir` is a **candidate**, not a tested permission recipe. `-p` is a real prompt argument here; do not claim that a bare `copilot --autopilot` exits after completing a headless task. Installed help says `--allow-all-tools` required for noninteractive while the programmatic reference documents selective grants: if narrow access is rejected or hangs, stop instead of widening. The [wrapper](../../scripts/headless.py) chooses stdin without `-p` and has **no verified real CLI stdin or JSONL schema**. Its paid execution needs explicit flags and disjoint preflight; it cannot certify task completion. [Headless and CI](headless-and-ci.md).

## Budget, stop and resume

`--max-autopilot-continues 3` caps *continuation messages*, not shell time, child processes, tool calls, money or network. Preview `/limits set max-ai-credits 30` (or `--max-ai-credits 30`) sets a **soft** session AI-credit cap: usage arrives after a model call, so one call can exceed it. Inspect `/limits` and `/usage`; `/limits unset max-ai-credits` only after checking current help and obtaining approval. Put independent time/credit ceilings around paid work; for offline verification `scripts.runner` has bounded outputs/timeouts but is not an assistant budget system. [claim:credit-limit]

Queue a steering correction with Ctrl+Q/Enter where supported; inspect `/tasks` and cancel a pending item before it starts if scope changed. Esc twice interrupts running work or background agents; **it is not rollback** for changed files, shells, or remote calls. Save the [nine-field handoff](sessions-and-context.md), exit, then resume an explicit session ID (not blindly the latest); re-inspect files, mode, tasks and grants. Use a human-reviewed disposable OS isolation layer if granting shell/network: the documented Linux bwrap and Windows limitations, remote MCP, inherited credentials, mounts and the Docker socket all matter. Broad permissions are limited to [scenario E](../scenarios/E-disposable-broad.md), not a fallback for this cycle. [source:cli-reference]
