# Autopilot: agree on an end condition first

Autopilot continues a task; it does not grant write permission, run your trusted checks, limit filesystem access or publish changes. Use it only after you can state what “done” means. The [first-hour stock filter](../start/first-hour.md) is a bounded example: validation already passes, feature acceptance fails, two files are editable, and a human will run checks **after** reviewing the diff.

1. In the repaired lab, check `in-stock` before edits using the shell-specific `practice.py check` command in [first hour](../start/first-hour.md); record exit 1. Inspect `/env`, `/permissions` and `/tasks`. Start the interactive session with only `view,grep,glob,edit` available as shown there; do not offer the agent shell execution.
2. Use `/plan` first and approve its file ownership and negative cases. If the task still benefits from continuation, toggle `/autopilot` in the interactive CLI and say: “Implement `in_stock=None|bool` only in `src/catalog.py` and `tests/test_catalog.py`; filter before pagination; preserve totals/default output; reject integers and invalid CLI input. Do not run shell or network. Stop after showing the diff and naming checks for a human to run; stop earlier on any unexpected path or permission request.”
3. Review each requested write in manual permissions. Inspect `/diff`, `/tasks`, `/usage`; `/exit` and use `practice.py diff` on **all lab files** before running `practice.py check` for validation and in-stock. Expect two exit-0 checks only after a correct implementation; Autopilot's completion message alone is not acceptance.

The CLI setting `stayInAutopilot` was reported as defaulting to `true` in captured help; if you want the mode to stop after a task, check `/settings stayInAutopilot false` in your session. Recheck mode after resume. `--max-autopilot-continues 3` limits continuation messages, **not** credits, time, child processes or tools. The preview `/limits set max-ai-credits 30` is a soft credit limit accounted after a call; inspect `/usage` and keep your own spending decision. Esc twice interrupts work but does not undo edits or external effects. If a narrow grant fails, stop rather than switching to `--allow-all`.

Headless Autopilot is a separate [advanced integration](headless-and-ci.md), not the next step for learning the native interactive path. [Permissions](permissions.md) separates tool visibility, approval and OS isolation; [sessions](sessions-and-context.md) covers the handoff after an interrupted task.
