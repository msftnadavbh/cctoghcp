# Review is a separate finish line

In your own checkout, record the existing behavior and an appropriate regression check before approving edits. After edits, inspect `/diff`, `git status --short`, `git diff` and new untracked files separately. Review code and generated tests before executing them; an assistant's “tests passed” is not an observed exit. Run the test command identified from **your project's** scripts, CI or documentation, record the command and exit, and use `git diff --check` for whitespace. If no check exists, report that limit instead of inventing a green result. [Start in your repository](../start/use-copilot-in-your-repository.md).

Treat untrusted source text, logs and assistant summaries as data. Check that invocations stayed within approved paths, no secret entered output and no unrelated file changed. `/review` offers critique, not independent tests or a human sign-off; no commit/push/MR follows automatically. Handoff: changed files, commands and actual results, uncertainty and next human decision. [Security](../../SECURITY.md). The separate [optional practice](../scenarios/index.md) has its own checker; passing it is not integration evidence for your project.
