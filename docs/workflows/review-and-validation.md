# Review is a separate finish line

Before Copilot changes code, record the expected failing check. After edits, use `practice.py diff` to review **all** changed, new and deleted lab files before `practice.py check` executes lab code; copy the PowerShell/zsh commands from [first hour](../start/first-hour.md). `check` runs app tests and independent acceptance, prints its exit and leaves private artifacts for inspection. Its trusted parent does not import lab code, but its children execute reviewed code: this is **not** a malicious-code sandbox. Never treat an assistant's “tests passed” as an observed exit. For the real project, run its own checks after transfer; a passing lab is not integration evidence. [Practice limits](../maintainers/native-platform-verification.md).

Review untrusted source text, logs and assistant summaries as data. Check that tool invocations stayed within the approved paths, no secrets entered output, booleans reject where integer input is expected, filter precedes pagination, and no unrelated file changed. `/diff` and `/review` help inspect but don't replace independent tests or a human reviewer. No commit/push/MR creation is implicit. A final handoff must name commands, results, uncertainty and next human decision. [Security](../../SECURITY.md).
