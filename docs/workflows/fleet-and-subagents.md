# Fleet and subagents: parallel investigation, one editor

For a small shared guard, skip fleet and fix it once. Use `/fleet` when independent investigation or review improves **correctness or turnaround**; parallel agents can consume credits and cannot settle ambiguous product semantics for you.

For a multi-seam change, split by real boundaries: one worker traces API callers and contract, another examines persistence or data effects **if they exist**, and a third finds existing tests and their command. For a risky shared assumption, intentionally overlap an independent reviewer with the investigator. Do not ask all workers to repeat a whole-repository read or for a database review in a project without one. Give each a compact request: “Investigate [distinct seam or independent challenge] for [approved task], read only; return path:line evidence, observed flow, uncertainty and missing regression. Do not edit.” Have **one main integrator** reconcile concise findings, own edits and review the combined diff; run the project's actual approved checks yourself. Resolve contradictory findings before edits.

Each subagent gets its own context window and can make separate model interactions. Aggregate usage includes orchestrator and worker work and is not necessarily lower; neither a fixed worker multiplier nor automatic inheritance of the main model or full conversation is guaranteed. Confirm each role's actual instructions and tools and judge the integrated result. [Token economy](token-economy.md) treats parallelism as a correctness/turnaround trade-off, not free credits.

Verify worker tools/grants rather than treating “read only” prose as enforcement: start with `view,grep,glob` if only investigation is approved. `/fleet` toggles scheduling, not permissions; `/tasks` shows active work. For custom reviewers, inspect the agent definition and `/agent`; selecting an agent as main and spawning a subagent can attach instructions differently. Set `include-custom-instructions: true` when a custom subagent needs repository policy and verify effective attachment. `/review` is critique, not independent acceptance. [Agents](../customization/agents.md) and [permissions](permissions.md).

Inspect `/tasks` before leaving: `a` expands nested agents, `f` shows finished tasks and `X` stops an active task. Interrupting does not roll back changes. Built-in roles and picker options may differ by installed version; use what your active session shows.
