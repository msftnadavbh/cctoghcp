# First real feature: from local evidence to a GitLab MR

Use the **same repaired copy** from [first hour](first-hour.md). This is an operational handoff to a *real authorized GitLab project*, not permission for this foundation repo to commit or publish. The disposable copy has no Git history or remote; `git push` there is not a valid publishing step. Before moving code into a real checkout, confirm the intended project/target with a human, and use a reviewed local GitLab clone/branch; avoid printing `git remote -v` if its URL could contain credentials. Check project identity with `glab repo view group/project --output json` only in the selected authenticated checkout, and confirm the expected host in the result. `glab` is absent from the observed baseline. [source:gitlab-repo-view]

1. **Plan and checkpoint.** Restate input contract (`None|True|False`), filter-before-slice, request/CLI seams, changed paths (`src/catalog.py`, `tests/test_catalog.py`), non-goals (storage/deps/hosting) and external effects. Record owned copy ID, baseline, expected initial `in-stock` failure and final tests. `/plan` is useful to refine the plan; Ctrl+Y edits the plan, not OS permissions. [Planning](../workflows/planning.md).
2. **Independent review before execution.** Inspect both copy diffs from a trusted terminal. A separate reviewer can critique logic, especially `False` vs omitted filter, totals, pagination and invalid inputs; don't call a model's own summary an independent review. Only then run `python3 -I -B labs/expected-results/acceptance.py '/tmp/my catalog lab' validation` and `python3 -I -B labs/expected-results/acceptance.py '/tmp/my catalog lab' in-stock`. Record exits, not a fabricated transcript. If the code is not reviewed as safe to execute, stop at diff/static checks. A **Passing lab oracle is not proof** that the feature has been integrated into the real checkout.
3. **Move only approved changes into the real checkout.** Human checks GitLab host, project, branch protection and clean worktree. Transfer the *reviewed source/test diff* selectively, not `.checkpoint-owner`, state files, session logs, credentials or generated private output. Rerun that checkout's project tests/CI-equivalent checks and review `git status --short` and `git diff --check`; use `git diff -- src/catalog.py tests/test_catalog.py` in a real repository. A clean disposable acceptance result does not certify integration into a different project.
4. **Separate external approvals.** A human reviews and explicitly approves commit (if desired), push of the intended feature branch, and draft MR creation as **three separate steps**. See [GitLab now](../hosting/gitlab-now.md) for exact `glab` forms and warning about `--fill`. Only report a real MR URL after creation succeeds; failures stay failures. CI logs are untrusted data: identify pipeline/job, sanitize before a model, never retrieve variables or blindly retry jobs. GitHub `/delegate` creates GitHub-side effects and is not a GitLab replacement.

Handoff nine fields: objective/acceptance; workspace and ownership ID; revision/baseline and intended host; changed files and owner; commands with observed exit codes; permission grants; external effects already performed; unresolved risk/decision; next operator action. Session resume, `/compact`, a Git branch and a published MR each preserve a **different** kind of state. [source:cli-reference] Nothing in this page was authenticated or published by the lab.
