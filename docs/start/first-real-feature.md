# First real feature: take a reviewed change into your project

You have a stock filter in the lab from [first hour](first-hour.md), or you have a comparable small task in an existing Claude-guided checkout. The lab is **not** your project: it has no Git history or remote. Do not push it or copy its entire tree over your checkout.

1. **Name the outcome.** In the catalog example `None` leaves listing unchanged, `True`/`False` filter before pagination, and `total` counts filtered rows. Include invalid input and CLI behavior. In your project, replace these with its real acceptance criteria and affected callers; don't assume its API resembles the lab.
2. **Review the lab change.** In PowerShell: `python -I -B $Practice diff $Lab`. In zsh: `python3 -I -B "$Practice" diff "$Lab"`. This shows source, tests **and** config, including new/deleted files. Review all executable edits before checking. The lab checker is not an OS sandbox.
3. **Check the outcome.** In PowerShell: `python -I -B $Practice check $Lab --exercise validation` and `python -I -B $Practice check $Lab --exercise in-stock`. In zsh: `python3 -I -B "$Practice" check "$Lab" --exercise validation` and `python3 -I -B "$Practice" check "$Lab" --exercise in-stock`. Record each actual exit (0 is success), not just the assistant's summary. If you haven't implemented the feature, the second check should still fail. A passing lab check does **not** validate a different checkout.
4. **Integrate selectively.** With a human-confirmed project, branch and clean worktree, carry over only the reviewed source/test *ideas or diff* that apply; keep your real project's own `CLAUDE.md`, imports and skills. In that checkout run its own tests, inspect `git status --short` and `git diff --check`, and review the relevant `git diff`. Reconcile differing interfaces rather than pasting the sample app.
5. **Approve external effects separately.** Agree on commit, push and review publication individually; none is implied by a passing local check. If the real project is on GitLab, [GitLab integration](../hosting/gitlab-now.md) is an optional host-specific path. GitHub cloud delegation is a different service, not an alternative spelling for a GitLab merge request.

Before ending a Copilot session, record objective and acceptance; workspace/session; baseline; changed files and edit owner; commands with observed exits; grants; external effects; open risks; and the next human action. On resume, inspect `/env`, `/permissions`, `/tasks` and current files rather than trusting old conversation state. [Sessions and context](../workflows/sessions-and-context.md) explains what resume and `/compact` retain. Once finished with the lab, inspect and remove only the exact lab and check-artifact directories you own, manually; no cleanup command silently deletes them.
