# Hosting boundaries and authentication

Copilot login, GitLab access through `glab`, and GitHub repository permissions are separate authorizations. Start with `copilot login` or `/login` for Copilot. For token-based use, `COPILOT_GITHUB_TOKEN` takes precedence over `GH_TOKEN`, then `GITHUB_TOKEN`; a fine-grained PAT needs Copilot Requests permission. Classic PATs are not supported. Use the [authentication guide](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli) for supported options. Protect the credential store: systems without a usable keychain can fall back to plaintext under `~/.copilot`. Never put tokens in repository files, command arguments or prompts.

Use the standalone `copilot` command, not the retired `gh copilot` extension. See [Windows and macOS installation](../start/use-copilot-in-your-repository.md#open-your-checkout) for native setup. Source hosting remains your choice; GitHub-hosted features require their own repository access.
