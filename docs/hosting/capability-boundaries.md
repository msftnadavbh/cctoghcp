# Hosting boundaries and authentication

Three identities are not interchangeable: (1) Copilot CLI authentication/entitlement (`copilot login` or `/login` in an approved environment), (2) GitLab project credentials for `glab`, (3) optional GitHub repository permissions for cloud agent/PR features. No login or token probe was performed here. For CLI token variables, `COPILOT_GITHUB_TOKEN` takes precedence over `GH_TOKEN`, then `GITHUB_TOKEN`; a supported fine-grained PAT needs Copilot Requests access; OAuth/Copilot/GitHub App token forms differ from classic `ghp_` PATs. Check current docs and enterprise policies rather than trying token types in this lab. Store secrets in reviewed keychain/HOME; note possible plaintext fallback under `~/.copilot`. Never put tokens in history, repo, command arguments, reports or examples. [source:cli-reference]

Optional npm installation (`npm install -g @github/copilot`) is a **user choice**, not first-15-minute setup; check its Node requirement and version before using. `gh copilot` is not the assumed modern CLI entry point. Only isolated CLI help/version was inspected; no authenticated command proves functionality. [Versions](../reference/versions.md).
